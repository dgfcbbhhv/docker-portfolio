# 红利持仓分析（生产自用部署）

个人实盘辅助分析工具：A/H/US 红利持仓、Kelly 参考仓位、李氏评分、因子 IC/IR、回测、预警。

## 快速启动（本地）

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.lock.txt
streamlit run app.py
```

## Docker 启动

```bash
cp .env.example .env   # 填入预警密钥（SMTP/Webhook/Telegram）
docker compose up -d --build
```

启动两个服务：

- `portfolio`：Streamlit 界面，端口 8501
- `alert-worker`：独立后台预警进程，不依赖界面是否打开

查看状态：

```bash
docker compose ps
docker compose logs -f alert-worker
```

预警密钥优先读取环境变量，`data/alert_config.json` 仅作界面配置的本地缓存。

## 数据与配置

- `config.json`：持仓、手动股息率、手动股价、Kelly 参数、预警阈值、数据新鲜度阈值
- `data/`：行情/财务/分红缓存、预警历史、Worker 状态（已加入 `.gitignore`）
- `notes/`：手动笔记与评分历史
- `requirements.lock.txt`：锁定版本，镜像安装以此为唯一来源

修改持仓或参数后，编辑 `config.json` 并重启服务即可，无需改代码。

## 后台预警

```bash
python -m modules.alert_worker
```

行为：

- 交易时段每 60 秒、非交易时段每 300 秒检查一次
- 发送失败自动指数退避重试，全部失败时按通道顺序降级并写入 `data/alert_failures.log`
- 同一预警默认冷却 240 分钟，避免重复轰炸
- 每次成功循环写入 `data/worker_heartbeat.json`，Docker healthcheck 依赖它

### 预警设置与触发条件

阈值在 `config.json` 的 `alerts` 段配置（下方为默认值）：

| 项 | 默认 | 触发条件 | 含义 |
|---|---|---|---|
| `price_drop` | 8.0 | 单日跌幅 > 8% | 股价大跌 |
| `div_change` | 0.5 | 股息率变动 > 0.5% | 分红数据变化 |
| `kelly_change` | 5.0 | Kelly 建议仓位变动 > 5% | 目标仓位大幅偏移 |
| `lishing_drop` | 10.0 | 李氏/成长评分下降 > 10 分 | 基本面转弱 |
| 数据新鲜度 | — | 行情 90 分钟 / 财务 7 天 / 分红 30 天 / 历史 7 天未更新 | 缓存过期，数据不可信 |

### 预警驱动的仓位管理（用仓位管理降低风险）

预警不是通知而已，应按"该建哪只、加多少、减多少"执行，且只在无新鲜度预警时动手：

| 收到预警 | 仓位动作 | 理由 |
|---|---|---|
| 新鲜度预警 | **冻结一切建仓/加仓**，先刷新数据核对 | 依据过期缓存调仓等于盲操；工具对缓存设了硬门禁而非静默兜底 |
| 股价跌幅预警 + 李氏 ≥ 70 且 组合约束 > 5% | 视为机会，**可建仓/加仓**，仓位=组合约束列 | 超跌买入是红利策略的核心收益来源；前提是评分未跌破加仓线，说明基本面没坏 |
| 股价跌幅预警 + 李氏 < 60 | **不加仓**，只持有 | 大跌+评分转弱双重信号，加仓等于向下摊平基本面变差的标的，违背止损纪律 |
| 评分下降预警（跌破 70） | 暂停加仓，仓位降至组合约束甚至更低 | 评分红线（审计/ST/现金流）任何一项即可归零；降级先减仓后观察 |
| Kelly 变化预警（单只建议 ±5%） | 按差额调仓：差 > 2% 加到组合约束，差 < −2% 减到组合约束 | Kelly 仓位变化来自胜率/赔率或波动率重估，跟随而非对抗模型 |
| `div_change` 预警 | 核对分红口径，必要时手动更新 `manual_div_yields` | 分红是股息率与 Kelly 胜率的主输入，口径错误会连锁污染评分 |

**为什么是"组合约束"而非 Kelly 原值**：Kelly 是算术最优投注比例，但把比例直接满仓在数学上会被单次大幅回撤击穿（对数财富曲线在超配时斜率骤降）。工具用 `quarter Kelly × 相关性折扣 × 波动率校准` 三层打折，再按层级上限（A 80%/HK 80%/US 60%/REIT 20%）与组合上限（80%）等比压缩，即"组合约束"列。它的数学含义是：**在不破坏红利组合长期复利的前提下，能承受约 10% 层级回撤红线仍不清仓的最大仓位**，比满仓 Kelly 更抗肥尾、更抗相关性共振。

**真实可信的依据（非拍脑袋）**：
1. **Quarter Kelly 有统计学依据**——Kelly 对胜率 p 与赔率 b 的估计误差极敏感，历史上按满 Kelly 下注的回撤远超 50%；0.25 倍是经回测与学术文献（如 Thorp 的 Kelly 实践）验证的保守折中，0.5 倍偏激进、0.1 倍偏保守，本工具取 0.25。
2. **波动率校准有实测意义**——高波动股票的 Kelly 建议会被折扣（基准 18%、指数 0.5、限 0.3~1.3 倍），因为波动率直接放大对数财富的方差，同仓位下高波动标的的破产概率更高。
3. **相关性折扣 = 防一荣俱荣一损俱损**——红利股内部相关度高（`CORR_BASE=0.75`），组合同时配置长江电力/神华/海油看似分散，实则同涨同跌；折扣把理论独立仓位压缩，避免在系统性回调中超配。
4. **分层上限 = 集中度控制**——单层超配会把一次行业黑天鹅变成组合级损伤；单只硬上限 `maxpos=30%` 保证任何一只暴雷损失 ≤ 组合 30%。
5. **"先看新鲜度再动手"** —— 你收到的每一条调仓建议都基于缓存行情，缓存过期则建议失真；工具显式拦截而非静默降级，正是为了杜绝在错误数据上做仓位决策。

## 数据新鲜度门禁

页面顶部会显示各缓存年龄；超过阈值（默认行情 90 分钟、财务 7 天、分红 30 天）会显式警告，使用手动股息率/股价兜底的标的一并提示。看到警告时，先刷新或核对数据，再决定是否操作。

## Kelly 参考区间

Kelly 输出为参考区间，不是精确仓位。`config.json` 中 `kelly.max_total` 是组合级总仓位上限（默认 80%），所有标的目标仓位合计超限时等比压缩，压缩后列显示为“组合约束”。

## 建仓 / 加仓操作指引

界面持仓看板每只股票展示三列 Kelly 仓位与一列“操作”结论，按以下规则解读：

### 1. 选哪只股票（操作列判定）

| 市场 | 🟢可加仓 | 🟡观望 | ⚪不加 |
|---|---|---|---|
| A股 / 港股 | 李氏评分 ≥ 70 且 组合约束仓位 > 5% | 李氏评分 ≥ 60 | 其余 |
| 美股 | 成长评分 ≥ 70 且 Kelly 仓位 > 0 | 成长评分 ≥ 50 | 其余 |

- **李氏评分（A/H）**：`lishing.py` 维度权重 PE15/负债10/ROE15/分红20/现金流10/PB10/市值5/审计5/质押5，权重按缺失维度回收；任何红线（审计异常 / ST / 连续两年经营现金流为负）直接归零。
- **成长评分（US）**：`signals.evaluate_growth` 基于 Kelly、PE 分位、均线多头排列。
- 只对“操作 = 🟢可加仓”的标的考虑买入/加仓；🟡观望保持持仓；⚪不加则不加仓。

### 2. 加多少仓位（Kelly 三列）

| 列 | 含义 |
|---|---|
| 波动校准 | `kelly_vol_adj`：Quarter Kelly × 相关性折扣 × 波动率校准（基准 18%，高波动打折、低波动加分，限 0.3~1.3 倍） |
| 因子仓位 | `kelly_factor_adj`：波动校准再乘因子 IR 乘数（因子 Tab 训练后生效，未训练为 1.0） |
| 组合约束 | `kelly_portfolio_adj`：因子仓位按层级上限（`layers.*.invested_cap`）与组合上限（`kelly.max_total`）等比压缩后的最终参考仓位 |

**建议仓位 = 组合约束列（%）**。当前占比 = “占比”列。差额 = 组合约束 − 占比：

- 差额 > 2% → “Kelly调仓路线”Tab 提示 **加仓**：从占比加到组合约束
- 差额 < −2% → 提示 **减仓**：从占比降到组合约束
- 差额在 ±2% 内 → 组合与建议基本一致，持有不动

### 3. 分层与总仓位约束

- 每层独立上限：A 80% / HK 80% / US 60% / REIT 20%（`config.json` `layers`，可改 `invested_cap`）。
- 层内所有标的 Kelly 合计超层上限时等比压缩；压缩后列标“组合约束”。
- 单只硬上限 `kelly.maxpos`（默认 30%）；组合级总上限 `kelly.max_total`（默认 80%）。

### 4. 执行前检查

1. 页面顶部无“数据新鲜度异常”警告（行情 90 分钟 / 财务 7 天 / 分红 30 天 / 历史 7 天）。
2. 目标股票不在“手动股息率/股价兜底”名单且李氏/成长评分无红色警示。
3. 成本分层 Tab：新增资金优先加仓“黄金档”（成本股息率 / 当前股息率 ≥ 1.2）；“警戒档”标的暂停一切加仓。
4. 最近未收到该标的的“评分下降/新鲜度”预警；收到预警时按“后台预警 → 预警驱动的仓位管理”章节处理。

> Kelly 与评分均为参考，不构成投资建议；实际下单前请结合人工复核。

## 主营业务估值（李/芒视角）

界面「主营业务估值」Tab 与每日选股推送均接入同一套估值引擎（`modules/valuation.py`）：

- **主营质量分** = ROE(50) + 经营现金流/净利润(30) + 资产负债率(20)，用整体财务代理主营成色（暂无分业务披露数据）
- **合理 PE** 由质量分按市场定价：A 股 8~20、港股 7~17、美股 15~35；**合理 PB** = 合理 PE × ROE
- **内在价值** = EPS×合理PE 与 BPS×合理PB 取保守小值（美股优先 PE 法）；**安全边际** = (内在价值 − 现价) / 内在价值
- **贵不贵**：便宜 / 合理偏低 / 合理 / 偏贵 / 昂贵；**值不值得买**：值得买 / 可以买 / 观望 / 贵了别追 / 回避（质量分过低或关键数据缺失时如实标注"数据不足"）
- **李嘉诚视角**：现金质量、低负债、股息垫、安全边际——先求不亏，再求赢
- **芒格视角**：好生意合理价，反过来想——再好的生意买贵了也是坏投资

每日推送在每只候选的理由中新增「估值贵不贵 / 值不值价值投资 / 李嘉诚视角 / 芒格视角」四行，落款附李、芒语录。估值结论仅供复盘，不构成投资建议。

## 模拟盘验证（先验证信号再上真钱）

界面“模拟盘验证”Tab 用东方财富真实行情驱动信号快照与虚拟组合执行，验证推送的买卖信号是否真实可信：

- 每日收盘快照生成信号评分，按 Kelly 建议生成 T+1 开盘挂单
- A 股按 100 股整手成交，买方向费用 0.1%，卖出加印花税 0.05%
- 涨停无法买入、跌停无法卖出、停牌/无行情、现金不足时记入未成交原因，不伪装成已成交
- 挂单周末顺延，信号验证至少积累 2 天快照后展示胜率与平均收益
- A/H 使用真实李氏评分，美股使用 `signals.evaluate_growth` 成长评分，不再用 ROE 冒充评分
- 信号验证同时统计相对中证红利（000922）的超额收益与超额胜率，避免牛市里绝对上涨造成假胜率

## 推送审计

每次推送写入 `data/push_audit.jsonl`，包含 `push_id`、内容哈希、通道、状态、重试次数、耗时与 `meta`（类型、市场、日期、数据新鲜度、选股列表）。

- `push_id` 用于真实成交回填关联
- `content_hash` 用于核对消息内容是否被篡改
- 每日选股推送在数据新鲜度异常时 fail-closed，不发送选股，只发“数据不可靠”提醒

## 人工跟单执行登记（长期持有模式）

推送发出后自动生成“待执行”记录（`data/execution_log.json`）。人工下单后在界面登记“已按推送下单 / 部分执行 / 忽略+原因”；导入券商成交后按 `push_id` 自动核验哪些代码实际成交，状态变为“成交确认 / 部分成交确认”。

## 分红收入登记（长期持有核心指标）

券商成交表不含分红派息，界面“真实成交对账”Tab 支持登记每笔到账分红（`data/dividend_log.json`）。对账摘要会同时展示已实现买卖盈亏、分红到账和“含分红总盈利”，避免长期持有被低估。

## 仓位管理（低频纪律）

界面“仓位管理”Tab 按优先级给出逐只结论：评分红旗/数据异常 → 停止或暂停加仓；成本档位警戒 → 暂停；单票达上限或加仓空间不足 → 持有；评分达标且空间 ≥ `add_gap` → 可加仓。同时展示层级余量、组合现金和单票超限数量，建议按结论低频执行，不因短期波动频繁调仓。

### 正金字塔加仓层级（`add_ladder`）

加仓空间按 **递减权重分层**（默认 `[0.5, 0.3, 0.2]`，即底仓多、越加越少），防止"每次都跌、每次都加"的连环下注：
- 任一硬门禁命中即整层持有：**成本档位警戒 / 评分低于买入线 / 已达单票上限 / gap < `min_gap`**。
- 每层输出建议加仓比例，逐层累计不得突破单票上限（`maxpos`）。
- 加仓台账取 `notes/cost_tiers.json` 的成本批次数（每批 = 一次加仓），按真实层级放量；首次无批次即首层。
- 配置：`config.json → add_ladder.max_steps/tiers/min_gap`。

### 单笔风险预算（`risk_budget`）

把"单笔最多亏多少"锁进公式：`单笔上限 = 总资产 × risk_pct ÷ 止损距离`。
- 默认 `risk_pct=1.5%`（每笔最多亏总资产 1.5%）、`stop_loss_pct=5%`（止损距离），按你设定的 5%-10% 取保守侧。
- 提供 `capital`（总资产）时启用，与 `add_ladder` 建议取小者；未提供则不约束（兼容旧调用）。
- 配置：`config.json → risk_budget.enabled/risk_pct/stop_loss_pct`。

## 真实成交对账（推送 → 模拟 → 实盘）

界面“真实成交对账”Tab 支持导入 A 股券商导出的成交明细（如 `Table_*.xlsx`，列含成交日期/证券代码/委托方向/成交数量/成交均价等）：

1. 解析、去重并保存到 `data/broker_trades.json`
2. 按「成交日期 + 代码」自动关联推送审计中的 `daily_picks push_id`（支持前一天推送，因选股为收盘后推送、次日成交）
3. 未自动关联的可在界面手动关联或解除
4. 对账摘要展示：真实成交数、已关联推送数、模拟盘匹配数、成交均价偏差、已实现盈亏与费用，按代码给出盈亏明细
5. 导入成交后自动回填人工执行登记状态，形成“推送 → 人工登记 → 真实成交核验”闭环

验收建议：至少连续 20 个交易日、推送关联率 ≥ 80%、模拟/真实成交均价偏差 ≤ 0.5%、含分红总盈利 > 0，再考虑放大实盘资金。

当前只先做 A 股真实成交导入；港股/美股成交导入后续按同一结构扩展。

## 生产使用边界

- 数据源为免费公开接口（AKShare/腾讯/新浪/yfinance/Baostock），可能延迟、限流或变更
- 回测存在幸存者偏差与假设口径，仅用于相对比较
- 本工具不自动下单，所有决策需人工复核；不构成投资建议
